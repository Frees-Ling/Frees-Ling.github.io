# 安全模型

## 1. 信任域

1. **公开浏览器**：完全不可信。
2. **公共静态产物**：可被任何人读取，不能含秘密。
3. **动态公共 API**：只接受最小输入，必须鉴权/限流/验证。
4. **本地 Studio UI**：仅本机入口，但仍需防 XSS、CSRF 和恶意文件。
5. **本地特权服务**：唯一可访问 Git、SQLite、文件系统和集成凭据的组件。
6. **外部供应商**：各自独立信任边界，最小权限凭据。

## 2. 密钥

- 1Password 是权威；持久配置保存 item/reference，不保存密钥值。
- 密钥只在调用时进入进程内存，禁止写日志、截图、测试夹具、浏览器 storage 或错误报告。
- 按用途拆分 token，尽量只读/目录级/短期；轮换流程必须文档化。
- 1Password Emergency Kit/恢复信息独立离线保存。

## 3. Owner 认证

- Studio 本地使用优先依赖本机边界与 1Password 解锁。
- 若未来提供网页 Owner mode，TOTP/一次性密码只做认证，不做数据加密。
- 认证设计必须覆盖重放、速率限制、锁定、恢复、会话撤销和安全 cookie。
- 在 threat model 完成前不开放公网管理写入。

## 4. Collection 威胁模型

必须防止：

- 路径穿越、文件覆盖、MIME/扩展名伪装、恶意压缩包、超额上传。
- 猜测 submission ID、列目录、读取或修改他人提交。
- 重放上传令牌、无限提交、脚本滥用和凭据泄露。

最低控制：不可预测命名空间、会话级能力令牌、服务器端隔离、大小/数量/类型限制、
速率限制、过期策略、恶意文件隔离、无公共列表 API、审计事件和负向自动化测试。

## 5. 内容与导入

- Markdown/HTML、SVG、DOCX、PDF 和图片元数据都视为不可信输入。
- 渲染器必须清理危险 HTML/URL；不执行导入文件中的脚本、宏或外部指令。
- AI 输出同样是不可信输入；结构化校验后才能进入内容模型。

## 6. 备份

- 使用成熟认证加密库与版本化 envelope；密钥来自 1Password。
- 上传成功不等于备份成功：必须验证远端对象、manifest、解密、数据库完整性和必要文件。
- 恢复在临时目录完成，验证通过后再切换；失败不得覆盖现有工作状态。

## 7. 发布与供应链

- 保持最小 GitHub Actions 权限，Dependabot PR 不自动无审查合并。
- 依赖更新检查公告、锁文件、构建、测试、浏览器回归和生成产物。
- secret scanning、依赖审计与构建产物扫描纳入后续安全阶段。
